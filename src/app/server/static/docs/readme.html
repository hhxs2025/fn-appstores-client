FN软仓服务端 · 使用指南

版本 v2.10.3（Go 版） · 纯在线托管模式 · 应用级变更审核 · 推送与安全防护

项目简介

FN软仓服务端是 FN软仓的管理后端。除提供 FN软仓自己的官方源给软仓客户端外，还内置了应用托管、变更审核、下载统计、外链加速、定向消息推送及完整的防刷安全机制。

v2.10.3 更新说明：新增定向消息推送（支持弹窗、强更）、异常行为告警（支持钉钉、飞书等）、设备黑名单封禁、管理员防爆破。同时客户端下载统计改为校验通过后主动上报，并进一步优化了外链加速器的故障切换逻辑。

三种参与方式

方式一 · 纯在线托管（推荐）

开发者不需要懂 Git，不需要建仓库，不需要写 JSON。向源主申请开通后，直接在网页后台填写应用信息。

  1. 申请入驻：在软仓客户端或网页端提交入驻申请。源主审核通过后，发送专属管理后台链接。
  2. 在线填表：在后台点「添加应用」，拖入 FPK 文件自动解析，填入下载直链。
  3. 提交审核：点击「保存并提交审核」。源主通过后，客户端 30 秒内可见。

方式二 · 自带 fnrc.json（传统模式）

如果你有多个应用，或者希望数据完全独立，可以手写一份 fnrc.json 并挂载在 Gitee/GitHub 上，然后将直链交给源主添加为“三方源”。此模式下一次审核后，后续更新只需修改 Gitee 里的 JSON 并 push，无需再找源主审核。

方式三 · 自建独立源（成为源主）

通过 Docker 部署 FN软仓服务端，自己当源主。你可以自己上传应用，也可以聚合其他服务端或 fnrc.json。

自建 API 说明：新版客户端在下载完成且校验通过后，会向服务端发送 POST /api/download/report（参数包含 app_id 和 platform）以进行下载计数。如果您的自建服务端不是本套 Go 源码，请实现该路由以正常统计下载量。

部署步骤

1. 准备环境

  • Docker 已安装
  • 一个公网可访问的地址（域名或 IP）
  • 安全组 + 防火墙放行 5660 端口

2. 准备数据目录

mkdir -p /vol1/1000/fn-appstores-server/data/{apps,icons,previews}

3. 启动服务端

docker run -d --name fn-appstores-server --restart unless-stopped \
  --network host \
  -e TZ=Asia/Shanghai \
  -e BASE_URL="http://你的域名或IP:5660" \
  -e ADMIN_PASSWORD="你的管理密码" \
  -e NOTICE_PASSWORD="公告员密码" \
  -e AUTO_CLEAN_DEV_UPSTREAM="false" \
  -v /你的数据目录:/app/data \
  ccr.ccs.tencentyun.com/hhxs2025/fn-appstores-server:2.10.3

4. 验证

curl http://127.0.0.1:5660/health
注意：BASE_URL 必须含端口，否则图标、截图、下载地址全都不可达。

5. 访问管理后台

http://你的地址:5660/admin

后台核心功能说明

模块 说明
消息推送 支持轻提示、弹窗、强制更新三种类型。可按全量、版本、架构、Client ID 定向推送。强更支持配置最新版本号和 FPK 下载直链。
异常告警 支持钉钉、企业微信、飞书、Bark、ntfy、Server酱等。触发限速、密码爆破等安全事件时自动推送到手机。
访问限速 针对 /apps/ 下载接口的 IP 滑动窗口限速。支持白名单。超限自动封禁指定秒数并触发告警。
安全防护 管理后台密码连续错误 5 次自动锁定 IP 10 分钟。支持在仪表盘一键封禁异常设备的 Client ID 或 IP。
外链加速 v4 自动测速排序 + 客户端候选切换。加速节点临时故障时会自动冷却降级，不影响客户端下载。
应用管理 支持全托管（FPK 在本地）或半托管（外链）。一键清理残留的孤儿 FPK 和图标文件。

开发者系统

纯在线模式，无需依赖 Gitee。开发者通过客户端或网页提交入驻申请 -> 源主一次审核开号 -> 开发者在线填表保存 -> 源主二次审核应用 -> 上线。整个过程无需接触任何外部代码仓库。

入驻流程

  1. 开发者在申请页填写源名称和联系方式提交。
  2. 源主在 /admin-review 的「入驻申请」Tab 通过审核。
  3. 系统自动生成 token 和空源，源主复制后台链接发给开发者。

应用审核流程

开发者在后台填完应用信息点击保存后，会进入 Pending（待审核） 状态。源主在 /admin-review 的「应用审核」Tab 看到变更记录。通过后，应用立即出现在客户端。

严格审核机制：由于源主负责托管开发者的数据，为了平台安全，开发者每次新增应用、修改版本、下架应用，都必须经过源主审核。

被拒绝后

  • 开发者在后台对应的应用卡片上会看到红色的「被拒绝」标签及具体原因。
  • 修改后重新点击保存即可再次提交审核。

从 2.9.x / 2.10.0 升级到 2.10.3

# 1. 备份数据目录
cp -a /你的数据目录 /你的数据目录_bak_$(date +%Y%m%d)

# 2. 停旧容器并删除
docker stop fn-appstores-server
docker rm fn-appstores-server

# 3. 拉新镜像
docker pull ccr.ccs.tencentyun.com/hhxs2025/fn-appstores-server:2.10.3

# 4. 用原数据目录启动（同上一条 docker run）

自动迁移机制：

  • 服务端首次启动 2.10.3 时，会自动扫描旧的 dev-accounts.json 和 upstream.json。
  • 系统会自动拉取开发者曾经在 Gitee 上的 fnrc.json，并将数据持久化保存到本地的 data/dev-sources/ 目录下。
  • 迁移完成后，旧的 upstream 记录将被清理或禁用，系统全面转向本地托管。

常见问题

Q1：客户端看不到新应用？

如果是新上传的，去后台点「刷新应用缓存」；如果是刚审核通过的，等待 30 秒（客户端有缓存），或让用户在客户端清除本地缓存。

Q2：三方源或加速器显示「离线」？

检查 URL 是否可访问，点「测试」看具体错误。加速器如果全部离线，服务端仍会强行下发原始直链或备用节点兜底，不会阻断下载。

Q3：强制更新（强更）怎么用？

在「消息推送」中选择「强制更新」类型，填入最新版本号（如 2.10.4）和对应的 FPK 下载链接。客户端收到后会阻断操作并提示下载。如果客户端版本已经大于等于目标版本，该消息会自动忽略。

Q4：如何封禁恶意刷量的设备？

在「仪表盘 -> 设备统计」中找到该设备，点击右侧的「封禁」按钮并设置时长（0 为永久）。系统会记录 Client ID 或 IP 到黑名单，后续请求直接返回 403。

Q5：如何配置应用的多架构（x86 / ARM）？

在开发者后台添加应用时，保持两条记录的「应用 ID」相同，但「适用架构」分别选择 x86 和 arm。客户端会自动根据用户的设备架构展示对应版本。

Q6：自建服务端如何对接官方源？

如果你使用的是客户端的“极客模式”，初始化后源列表为空。请在「源管理」中点击添加，输入官方源地址 http://nas.hhxs2025.top:5660。如果你拥有自己的服务端，也可以在服务端的「三方源管理」中添加上游源进行聚合。
