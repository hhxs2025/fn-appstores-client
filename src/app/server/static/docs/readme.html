飞牛 fnOS · 应用商店部署系统

FN软仓：不是又一个商店，
是开商店的工具

一个飞牛 NAS 系统（fnOS）的三方应用商店部署系统。它由两半组成：一个能自己部署的服务端，一个装在飞牛里的客户端。

服务端跑起来，你就有了一个「源」。

客户端装进去，你就有了一个「前台」。

两半可以只用一半——不想折腾的人光装客户端就行，只想做后端的人服务器跑起来就能收工。

下面按「有哪几个部件、各自能干什么、三种情况怎么用」来讲。

一两个部件，可以只用一半

服务端是「源」，客户端是「前台」。

服务端跑起来，你就有了一个可被客户端连接的源；客户端装进去，你就有了逛和装应用的界面。两半可以只用一半：只想装应用，光装客户端；只想做源，服务端跑起来就能收工。

1服务端

默认是一个 Docker 镜像，5660 端口，IPv4/IPv6 双栈；也提供 docker 版 FPK，可以在飞牛应用中心直接安装，不必手敲 docker run。当前最新版是 2.12.0，新增了服务端 Webhook 通知和开发者后台 Webhook 通知。跑起来之后浏览器打开就是完整后台：上货、开发者、统计、加速线路、推送、邮件和 Webhook，全在里面。

2客户端

是一个 FPK，装到飞牛应用中心。它自己不带内容，内容全来自它连的「源」。

3不用记组合

实际只用记三种姿势：

  • 只装客户端：用户模式接官方源，或极客模式接别人的源。
  • 只跑服务端：得到一个纯后端源，谁的客户端都能连，开发者也能往上上货。
  • 两个都上：自己的源加自己的前台；要对外开放，再把地址发出去。

记住这三种姿势就够了，不需要把服务端和客户端拆成四种组合来背。

二客户端有两个模式，这个选择决定一切

第一次打开会让你选，之后按这个模式走。

1用户模式

预置官方源，且官方源是第一默认源、锁死删不掉。界面就是个正常商店：搜、看、装、更新。

源管理里也可以自己加源，但加进来的源不是第一默认源，也不提供公告和轮播图——公告和轮播图只由第一默认源（官方源）下发。

后台每次启动会把官方源地址强制覆盖成默认值，所以旧地址被换掉时你不需要手动改。

2极客模式

不预置任何源，启动时还会把残留的官方源槽位清掉，第一次进来是空的，要你自己填源地址。

极客模式说白了就是另起炉灶建一个应用商店：官方源被清掉，你自己填的第一个源就是默认源，公告和轮播图由它下发——通常就是你自建的服务端。你填几个源都行，但只有第一个源负责公告和轮播图，跟用户模式里官方源的角色一样。

所以两种模式的区别是：

  • 用户模式是「官方给你一个商店」——官方源是默认主场，别的源能加，但公告和轮播图只认官方源。
  • 极客模式是「你自己开一个商店」——官方源清掉，第一个源（一般是自建服务端）接管公告和轮播图，自己运营、自己掌控。

能接自建的源，也能接友店的源，还能两家一起接。多个源并发拉取，合并时按「应用 ID + 平台」去重，同名同平台只留版本高的那个，所以接三个源不会看到三条重复记录。

2上货：三种方式同时开着

自己传——服务端全托管模式。 选一个 FPK，服务端把 manifest 拆开，名字、版本、架构、简介、依赖、标签全读出来；图标从包里抽出来，转成 PNG 并压到 2048 以内；上传完应用就在列表里了，不用再填表。上限单包 512 MB，批量一次 2 GB，截图单独换，单次 64 MB。不想下载再上传，就贴个 URL 让服务端自己去拉。

挂外链——服务端半托管模式。 只登记元数据，下载地址填 FPK 直链。客户端点安装，服务端回 302 把请求甩过去，包不经你的机器。你 NAS 上只多一条记录，不多一个字节。外链建议优先选国内的 Git 类平台，如 GitCode、Gitee 等，也支持 OSS 存储；如果非要填 GitHub 直链，需要在后台配置加速站。

招商——开发者系统模式。 开发者申请入驻，你审批，系统发他一个 Token。之后他自己登后台传包、改简介、提版本，提交的改动进审核队列，你点了通过才生效，通过或驳回都会给他发通知。每个开发者自动汇总成一个独立子源，他不用建仓库、不用买服务器、也不用知道源文件该长什么样。

3分发：一次安装要过四道

客户端点「安装」之后，服务端要决定这个包从哪儿出去：

  1. 本地有这个 FPK → 直接给文件
  2. 只登记了外链 → 302 跳过去
  3. 半托管 + GitHub 外链才走加速 → 仅当应用走半托管模式、且 FPK 下载地址是 GitHub 直链时，后台配置的加速站才参与：服务端定时探测（默认 10 分钟一轮，单次探测 10 秒、抓 0.5 MB），按实测速度排序，最多 10 条写进下发列表。全托管本地文件、非 GitHub 外链不走这条
  4. 客户端逐条试 → 首包 5 秒没动静就换下一条，整轮 50 秒封顶

下载地址是每次请求现算的，不是写死在包里。所以你换线路、加镜像、改目录，已经发出去的客户端不用动。

运营后台还能看到：下载量按应用 / 按天 / 按平台分开记（同设备 60 秒内重复下载只算一次）、设备明细与在线离线、终端评分、定向推送、限速与封禁、data/ 整包备份恢复。通知同时走邮件和 Webhook，覆盖开发者申请、待审、源状态变化、上架 / 下架 / 更新、每周周报；同类事件一轮检测合并，不刷屏。

4开发者：一套完整的分账台

申请 → 审批 → 发 Token → 自助提交 → 变更审核 → 通知 → 数据看板。

开发者能看到自己应用的下载量、上架状态、被驳回的原因，也能自己撤回还没审的改动。

2.12.0 起，开发者后台也可以配置 Webhook，应用上架 / 更新的审核通过或驳回会直接推给开发者，不用反复登后台看结果。

这套东西的意义是：你想让别人往你的商店上货，不用先教他写 JSON。

四三种玩法

玩法一自建服务端

适合：有一堆自己的包要发、想完全掌控自己的商店。

  1. 安装 FN软仓服务端（docker 版 FPK），搭建自己的应用商店。
  2. 安装时需设置 服务端外部访问地址（公网地址可以是穿透或反代的 IP 或域名）和 服务端后台管理密码（默认 admin123）。
  3. 应用添加：拖入上传应用，根据实际确定是否勾选 托管 fpk 到服务端 和 托管 ICON 到服务端。若服务器或飞牛上行带宽有压力，建议不要勾选托管 fpk，fpk 改走外部直链。
  4. 若选择 半托管模式，上传 fpk 自动写入 json 后，进入 应用编辑 检查表单信息，填入「下载地址」（fpk 直链）。建议优选国内 Git 类平台，如 GitCode 或 Gitee 等，也支持 OSS；如填 GitHub 直链，需配置加速站。
  5. 轮播图：存到服务端 data/previews/lunbotu/ 下，地址填 http://xxx.yyy.com:5660/previews/lunbotu/xxx.webp（推荐 webp 格式）。跳外部链接填 ...xxx.webp|url:https:yyy.zzz.com；跳应用详情填 ...xxx.webp|app:应用id。尺寸建议 880×405px，也可直接填外部图片直链。

接自己还是申请聚合，二选一：

  • 要搭建完全独立的个人应用商店：服务端准备好后，安装 FN软仓客户端，首次进入选 极客模式，在 源管理 填入 http://xxx.yyy.com:5660，从服务端后台 刷新应用缓存，再在客户端「应用」里点 刷新。
  • 不搭建独立商店：把 http://xxx.yyy.com:5660 发给 FN软仓官方主源管理员，申请聚合，用户打开官方客户端即可看到你的应用。

玩法二外部 json 型玩法

适合：不想跑服务端，只想把自己的包挂出来。

  1. 从 FN软仓客户端安装 FN软仓助手 fpk，或从交流群下载 FN软仓助手 exe。
  2. 拖入 fpk 应用，自动读取元数据、写 json，手动填入 fpk 直链、图标直链等，点击「下载」导出 fnrc.json，存放到能生成直链的平台（如 Gitee / OSS 等）或 FNOS 的应用里（如 file-vault、轻量应用存储等）。
  3. 将 fnrc.json 告知 FN软仓服务端管理员，申请聚合。

玩法三服务端开发者系统子源玩法

适合：开发者只想发自己的包，不想建仓库、不想买服务器。

  1. 从 FN软仓服务端管理员处获取开发者申请地址（http://xxx.yyy.com:5660/dev/apply）。
  2. 填写源名称、作者名、联系方式，提交。
  3. 管理员审核通过后，用管理员给的后台地址进入，上传 fpk 读取并写入应用信息，手动填 fpk 直链，保存，提交，等待审核。
  4. 可在后台配置 Webhook（2.12.0 新增），应用上架 / 更新的审核结果会直接推给你，不用反复登后台看。

五跟友店是什么关系

不是竞品，是不同层。这话不是客套。

友店做的是内容运营：把应用聚起来、维护源站、跟着版本更新、扛住流量。这活又累又不讨好，总得有人干。

FN软仓做的是工具。友店愿意，可以拿它当后端；普通用户装了 FN软仓客户端，在极客模式里把友店的源加进来，照样逛、照样装。

客户端连图标的地址都做了兼容——友店把加速前缀写死在图片地址里，它也能剥掉重找，图片不会白一片。

所以你装它，不用卸掉别的。它更像个能同时看几家店的前台。

六从哪开始

想清楚你属于哪种人：

  • 只想装应用 → 装客户端，用户模式
  • 有自己的包要发 → 玩法一：自建服务端，客户端极客模式接自己，或申请聚合
  • 不想跑服务端、只想挂包 → 玩法二：FN软仓助手导出 fnrc.json
  • 只想发自己的包 → 玩法三：找源主申请开发者账号
  • 想运营一个对外商店 → 玩法一 + 配 BASE_URL 和 ADMIN_PASSWORD + 加速线路 + 开放开发者入驻 + 邮件 / Webhook

商店可以有很多个。开商店的工具，之前没有。
