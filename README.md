## 📖 应用简介

FN软仓是飞牛 OS 上的第三方应用商店客户端，支持**多软件源聚合**。用户可以自由添加自托管服务端地址，浏览、安装、更新飞牛官方应用中心没有的三方应用。

- **项目地址**：[https://gitee.com/hhxs2025/fn-appstores](https://gitee.com/hhxs2025/fn-appstores)
- **服务端镜像**：`docker pull ccr.ccs.tencentyun.com/hhxs2025/fn-appstores-server:2.9.0`
- **平台**：飞牛 OS
- **架构**：x86 / ARM 双架构兼容
- **开源协议**：MIT

> **架构支持说明**：单 fpk 内含 `fn-appstores-client-amd64` 与 `fn-appstores-client-arm64` 双二进制，`cmd/main` 按 `uname -m` 自动选择。安装逻辑已适配用户卷（`/vol*/@appcenter`）与系统分区（`/usr/local/apps/@appcenter`），支持 `install_type = root` 应用。
>
> **微应用支持**：v2.9.0 起声明 `micro_app=true`，可在飞牛应用中心宿主环境内加载，跟随系统主题。

## ✨ 核心功能

### 应用管理

- **多源聚合**：从所有启用的软件源并发拉取应用列表，按 `id@platform` 自动去重
- **树状聚合**：官方源可聚合多个三方源应用，无需手动添加即可发现更多应用
- **分类筛选**：15 个固定分类 + Docker/原生类型筛选 + 按源筛选
- **排序**：支持按名称、下载量、更新时间排序
- **全局搜索**：侧边栏顶部搜索框，任意页面可直接搜索
- **架构自动适配**：启动时检测本机架构，不兼容的应用自动过滤

### 安装与更新

- **多线路下载（v2.9.0 新增，配合服务端 v4 加速器）**：从服务端获取候选 URL 列表（`download_urls` 数组），依次尝试，某条线路失效自动降级到下一条；全部失败时回退原始外链。服务端 v4 加速器生成候选列表，客户端负责调度决策
- **实时进度**：WebSocket 推送下载进度、速度、当前尝试线路等信息
- **完整性校验（v2.9.0 强化）**：gzip 魔数 + HTML 错误页检测 + hash/size 校验（服务端提供时启用），多层防护，避免错误页被当作 FPK 安装
- **加速器失败上报（v2.9.0 新增）**：所有线路下载失败时，客户端主动 POST 到源服务端 `/api/accelerator/report-failed`，服务端据此给对应加速规则降权
- **Docker 应用验证**：容器必须 `running` 才算成功，失败自动清理残留容器
- **依赖缺失引导（v2.9.0 新增）**：识别飞牛返回的依赖缺失报错，一键跳转飞牛应用中心安装依赖
- **手动安装入口**：应用页工具栏「手动安装」，支持本地 FPK 上传，显示完整安装日志
- **客户端自更新**：设置页一键检测最新版本，下载后引导手动安装

### 应用评分

- **5 星评分**：详情页内点击星星打分，本地记录"我的评分"
- **评分展示**：应用卡片名称右侧内联显示平均分（★ 4.5）
- **用户身份聚合（v2.9.0 强化）**：通过统一网关注入的 uid 识别用户，回退到本地 client_id

### 软件源管理

- **添加/删除/启用/禁用**：填写名称和地址，测试连通性后添加
- **状态检测**：源列表显示在线/离线/已禁用，状态缓存 5 分钟
- **官方源保护**：官方源不可删除，地址隐藏显示
- **官方源地址自动迁移**：老用户升级后自动替换内置源地址

### 界面与体验

- **飞牛统一网关**：通过 `/app/fn-appstores-client` 访问，复用飞牛登录态，自动适配 HTTPS
- **系统主题跟随（v2.9.0 新增）**：通过飞牛 SDK 读取系统主题并实时监听变化；用户手动切换后优先用户选择
- **HTTPS 图片代理**：HTTPS 页面下 HTTP 图片自动走同源代理
- **轮播图双链路兜底**：支持 `v6URL|v4URL` 双地址格式，主地址失败自动降级
- **开发者星球**：3D 球面可视化开发者，拖动旋转、滚轮缩放、悬停查看
- **深色/浅色主题**：一键切换，偏好保存至浏览器
- **骨架屏加载**：首次加载显示灰色占位卡片，避免空白

## 📜 版本记录

### v2.9.0（当前版本）

**多线路下载 + 完整性校验 + 依赖引导 + 系统主题跟随 + 加速器失败上报**

**✨ 新增**
- **多线路下载**：从服务端 `/api/app/:id` 获取候选 URL 列表（`download_urls` 数组），依次尝试；某条线路失效自动降级到下一条，全部失败回退原始外链
- **进度可视化**：下载进度显示"正在尝试线路 X/Y"，直观了解当前使用哪条线路
- **加速器失败上报**：所有候选线路均失败时，主动 POST 到源服务端 `/api/accelerator/report-failed`，服务端据此给对应规则降权（配合服务端 v4 加速器）
- **依赖缺失引导**：识别飞牛返回的依赖缺失报错，一键跳转飞牛应用中心安装依赖
- **系统主题跟随**：通过飞牛 SDK 读取系统主题并实时监听变化，用户手动切换后优先用户选择
- **微应用声明**：`manifest` 新增 `micro_app=true`，可在飞牛应用中心宿主环境内加载

**⚙️ 优化**
- **下载完整性校验强化**：gzip 魔数 + HTML 错误页检测 + hash/size 校验（服务端提供时启用）
- **评分用户身份聚合**：通过统一网关注入的 uid 识别用户，回退到本地 client_id
- **WebSocket 协议扩展**：`install` 事件新增 `download_urls` 字段，同时保留 `download_url` 兼容旧服务端

**🔌 兼容性**
- **向前兼容 2.8.x 服务端**：新接口不可用时自动回退旧的单 URL 302 路径
- **服务端 v4 加速器对接**：配合服务端 v4 使用，客户端自动读取 `download_urls` 数组；如服务端未升级，回退 `download_url` 单地址
- **x86 / ARM 双架构**：单 fpk 内同时打包 amd64 / arm64 二进制，安装时自动选择

> **与服务端 v4 加速器的配合**：服务端 v4 在 `/api/apps` 和 `/api/app/:id` 中下发候选 URL 列表；客户端优先读取该数组，按顺序尝试。服务端只负责生成候选列表，不做预检；客户端负责实际调度决策，失败时自动切换并上报。老服务端（无 `download_urls`）自动回退单地址 302 流程。

## 🖥️ 服务端信息

客户端需要配合 **FN软仓服务端** 使用，服务端负责聚合应用列表、下发候选下载地址、维护加速器规则、公告和轮播图。

- **服务端镜像**：`docker pull ccr.ccs.tencentyun.com/hhxs2025/fn-appstores-server:2.9.0`
- **服务端仓库**：[https://gitee.com/hhxs2025/fn-appstores](https://gitee.com/hhxs2025/fn-appstores)

服务端 v2.9.0（v4 加速器）的核心能力：
- **候选 URL 列表下放**：`/api/apps` 与 `/api/app/:id` 返回 `download_urls` 数组
- **加速器健康检查**：定期探测各加速站可用性
- **失败上报接收**：`/api/accelerator/report-failed` 接收客户端上报，动态调整规则
