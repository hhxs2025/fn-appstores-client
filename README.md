# FN软仓客户端 v2.11.2

> 飞牛 OS 第三方应用商店客户端 · 多软件源聚合 · 可无限裂变的独立应用分发平台

---

## 📖 应用简介

FN软仓是飞牛 OS（fnOS）上的第三方应用商店客户端，支持**多软件源聚合**。它不只是一个软件仓库，更是一&#x4E2A;**「可无限裂变」的独立应用分发平台**——用户可以自由添加自托管服务端地址，浏览、安装、更新飞牛官方应用中心没有的第三方应用。

客户端本体是一个 Go 编写的本地服务，搭配原生 HTML 模板与 JavaScript 页面：默认通过飞牛统一网关以 Unix Socket 挂载（`/app/fn-appstores-client`），也支持独立端口模式（默认 `5660`）；安装、更新、卸载等动作统一走飞牛 `app-center/v1` 官方接口，不改动系统组件。

> **架构与机器码识别**：设备标识优先读取飞牛底层注入的机器码 `TRIM_SYS_MACHINE_ID`（生成 `fnos_` 前缀 ID），确保重装系统后不产生虚假新设备；取不到时依次回退 `/etc/machine-id`、本地缓存 ID，最后才生成随机 UUID。系统架构（如 `fnos-amd64`）通过 `TRIM_SYS_ARCH` 与请求头精准上报，解决 WebView 读取 UA 显示 Win32 的历史遗留问题。版本号由 `TRIM_APPVER` 或包内 `manifest` 注入，不在源码中写死。

> **✅ v2.11.2 核心变化**：日志新增时段筛选预览并放宽留存（15 日滚动 / 5M 上限）；Docker 应用安装进度分阶段提示，避免「假卡死」误操作；修复覆盖安装跳过向导导致的必填字段缺失报错；并补齐图片缓存预热与缓存管理面板。全部改动都在客户端侧，**服务端无需随本版本升级**。

## ✨ 核心功能

### 安装可靠性加固

- **安装记录自愈**：自动识别「系统认为已安装、磁盘上实际不存在」的残留记录（错误码 `10236` 已安装 / `10370` 无可用更新），保留用户数据卸载后重装；全新安装、应用更新、安装升级、版本降级四条路径全部接入。
- **多存储空间自适应**：安装卷由 `install/info` / `update/info` 与存储卷列表动态解析，更新时装回原卷；ARM 设备无存储空间 1、多盘位设备均可正常安装。
- **依赖引导直达应用中心**：缺失依赖时跳转飞牛应用中心，不再绕到系统设置。
- **手动安装修复**：选择本地 `.fpk` 后解析包内 `manifest` 取得真实应用名并直接完成安装。
- **向导字段兜底（v2.11.2）**：覆盖安装（同版本重装）也会重新弹出安装向导收集必填字段；首次填写的向导字段按应用名缓存到浏览器本地，`install/info` 因「已安装」拿不到向导配置时自动复用，避免 `wizard required field wizard_admin_password not found` 一类必填字段缺失报错；应用更新沿用系统侧旧配置，不重复弹向导。

### 下载与线路

- **服务端实时选线**：安装第 1 条候选即服务端实时选线入口，无需刷新即拿到当前最优线路；结合成功率与速度动态排序，坏线路靠后。
- **图标 / 图片多线路回退（v2.11.2）**：剥掉写死的加速前缀后，按「直连 → 加速池前 4 → jsDelivr → 原址」依次尝试，失败显示占位图；Gitee / GitCode 的 `blob` 链接自动转 `raw`。
- **本地缓存体系（v2.11.2 调整）**：图标 / 预览图 / 轮播图落盘缓存 30 天，FPK 缓存到 `appcenter-downloads` 且校验通过后可直接复用；新增启动 45 秒自动预热、列表加载后批量预热、打开详情按应用补热（10 分钟节流），设置页提供缓存统计 / 清空 / 导出 / 手动预热面板。日志保留策略调整为 **15 日滚动清理 + 5M 大小上限**（时间优先、大小兜底），日志内 URL 与源地址自动脱敏。

### 消息、统计与分发

- **系统级定向消息推送与强更**：WebSocket 实时通道 + 待拉取消息接口，支持定向推送、强制更新拦截与设备统计。
- **精准下载统计**：下载校验通过后才计数；主源地址永远排候选第 1 位，保证统计准确与 302 兜底。
- **应用评分**：应用详情页 1–5 星评分，按应用转发到所属源并回显平均分与评分人数。
- **卸载数据真正可清除**：卸载勾选清数据后确实删除 `@appdata`，不留残留。
- **弱网防丢容错**：首包超时放宽至 5 秒、整轮 50 秒；失败上报带 URL，服务端可定位规则并降权。

### 应用管理与辅助工具

- **应用管理**：已安装应用详情页支持启动 / 停止 / 重启 / 卸载，以及「强力修复」（清理关联 Docker 容器与残留记录后重装）；升级失败自动回滚（本地备份 FPK，不依赖服务端保留旧版）。
- **配置备份恢复、一键诊断、应用收藏、按开发者排序、公告未读红点**：应用配置以 zip 备份 / 恢复 `@appdata`（恢复后自动重启应用）；诊断报告汇总 `appcenter-cli status` 与应用日志末 500 行。
- **双模式首次启动引导**：用户模式预置官方源；极客模式不预置任何源、可自定义源并清理残留的官方源槽位，独立自更新隔离，数据自动净化。
- **首页数据看板**：顶部统计卡、自动轮播图（兼容三种数据格式，定向跳转 / 点击看大图）、公告记录、四列快捷卡片（已安装 / 可更新 / 热度榜 Top 10 / 新应用）。
- **日志时段筛选预览（v2.11.2 新增）**：设置页「查看日志」提供全部 / 近 1 时 / 近 6 时 / 近 24 时 / 7 天 / 自定义起止六档筛选，**仅用于预览**（后端默认最多返回最近 500 行）；「导出日志」始终导出完整文件，便于精准排错。
- **Docker 安装进度提示（v2.11.2 新增）**：安装阶段按等待时长切换分阶段文案并显示已用时，Docker 应用提示「正在拉取镜像 / 创建容器」，native 应用使用中性文案，并附「请勿重复点击或离开页面」，减少大镜像拉取期间「看似卡死 → 手动干预 → 安装失败」。

## ⚠️ 使用注意事项

1. **必须配合服务端使用**：客户端需搭配 FN软仓服务端，兼容 **v2.10.4 及以上**，服务端无需随本版本升级。升级顺序建议「先服务端、后客户端」。
2. **版本升级提示**：若从 v2.8.4 及以前版本升级而来，需升到 v2.9.0 及以上，应用更新功能才真正可用。
3. **日志留存与筛选**：v2.11.2 日志为 15 日滚动 + 5M 上限，**超期或超限的旧日志会被自动清理**；时段筛选只影响预览结果，点「导出日志」始终导出当前完整日志文件。
4. **Docker 应用安装耗时**：带管理后台 / 数据库的大镜像应用，首次安装需完整拉取镜像并初始化，耗时较长属正常现象，**与设备网络及镜像源速度有关**；安装期间请保持页面打开、勿重复点击或强制关闭，以免留下「系统已登记、实际未完成」的残留记录。
5. **残留记录处理**：遇到「已安装」却打不开、更新报 `10370` 等残留情况，v2.11.1 起客户端会自动识别并保留数据重装；如仍有异常，可用应用详情的「强力修复」。
6. **架构与存储卷**：客户端会自动识别 x86 / ARM 架构与目标存储卷；ARM 盒子、无存储空间 1、多盘位设备均可正常安装，无需手动改配置。
7. **源与图片**：添加第三方源后如出现图标空白，多为源站图片线路不通，客户端已内置多线路回退；加速线路顺序仍以服务端测速结果为准，客户端不参与测速与排序。极客模式不预置官方源，需自行添加后才会有应用数据。
