## 宣传图

## 📖 应用简介

FN软仓是飞牛 OS 上的第三方应用商店客户端，支持**多软件源聚合**。它不仅仅是一个软件仓库，更是一&#x4E2A;**"可无限裂变"的独立应用分发平台**。用户可以自由添加自托管服务端地址，浏览、安装、更新飞牛官方应用中心没有的三方应用。

**项目地址**：[https://gitee.com/hhxs2025/fn-appstores](https://gitee.com/hhxs2025/fn-appstores)

**服务端镜像**：`docker pull ccr.ccs.tencentyun.com/hhxs2025/fn-appstores-server:2.11.0`

**平台**：飞牛 OS

**架构**：x86 / ARM 双架构兼容

**开源协议**：MIT

> **架构与机器码识别说明**：客户端会优先读取飞牛底层系统注入的机器码（`TRIM_SYS_MACHINE_ID`）作为设备唯一标识，确保**重装系统后不产生虚假新设备**。系统架构（如 `fnos-amd64`）通过请求头精准上报，解决 WebView 读取 UA 显示 Win32 的历史遗留问题。

> **✅ v2.11.1 核心变化：安装链路全面加固 + 本地缓存体系**。
> 安装与更新不再被"系统里认为装过、磁盘上其实没有"的残留记录卡死，多存储空间设备（含 ARM 无存储空间 1、多盘位）自动选卷；图标与预览图首次进界面即全量落盘，之后 30 天源站零请求——顺手把图标加载慢、源站被反复拉图的问题一起解决。

## ✨ 核心功能

### 安装可靠性加固（v2.11.1 重构）

**安装记录自愈**：飞牛的应用安装状态记录在系统数据库中，当应用目录被意外删除（磁盘写满、安装中断、手动清理）时会留下"系统认为已安装、实际文件不存在"的残留记录，此时安装报 `10236 已安装`、更新报 `10370 没有可用更新`，两条路都走不通。v2.11.1 会自动识别这类残留记录，走一次**保留用户数据**的官方卸载（`deleteData: false`，`@appdata` 配置不丢）后重新安装，用户不需要手动去系统里删东西。

**四条路径统一兜底**：全新安装、应用更新、安装升级、版本降级全部接入同一套自愈逻辑，不再只有某一条路径能恢复。

**多存储空间自适应**：安装卷不再固定为存储空间 1。客户端按 **① 更新时取系统记录的 `installedVolumeID`（装回原卷，不跨盘）→ ② `install/info` / `update/info` 返回的卷 → ③ 本机探测（`TRIM_APPDEST_VOL` → `/vol*/@appcenter` → `/vol*`）→ ④ 兜底** 的顺序动态确定，ARM 盒子刷飞牛、无存储空间 1、多盘位设备均可正常安装。

**依赖引导直达应用中心**：安装前预检发现依赖缺失时，"去安装依赖"跳转飞牛**应用中心**而不是系统设置，一步到位。

**手动安装修复**：应用页的「手动安装」选择本地 `.fpk` 后，客户端解析包内 `manifest` 取得真实应用名并**直接完成安装**，不再只是把文件传上去。

### 下载与线路（v2.11.1 调整）

**更从容的超时预算**：单线路首包看门狗 2 秒 → **5 秒**，停滞检测保持 5 秒，单次安装整轮预算 25 秒 → **50 秒**。弱网、跨境线路、大体积 FPK 不再动不动就"所有线路不可用"。

**加速线路策略保持不变**：测速、排序、下发仍由服务端负责，客户端只按服务端下发的顺序依次尝试，不在本地测速、重排或随机。

**风控适配**：拉取源索引、加速池、图片时统一使用浏览器 UA，避免被 GitHub / Gitee 的风控页面顶成空结果。

### 本地缓存体系（v2.11.1 新增）

**图片落盘缓存**：所有图标、预览图、轮播图经客户端代理转发后落盘到 `@appdata/fn-appstores-client/{icons,previews,cache}`，默认 **30 天**有效，到期由后台任务自动清理。图标与预览图按**渲染语义**归类，不受源站文件名影响（`1.png`、随机哈希名同样进 `icons/`）。

**FPK 包缓存**：下载完成的安装包缓存到飞牛系统的 `/appcenter-downloads/{应用名}-{版本}-tpk/`，同一版本重复安装直接命中本地，不再重新下载；目录不可写时自动回退到 `@appdata` 下的应用目录。

**图片预热**：进入应用列表后后台批量拉取全部图标与预览图（10 并发、单图最多 3 条候选），源站只在首次被请求一次；打开应用详情时再补该应用的预览图。设置 → 系统 → 缓存管理 提供「立即预热」与进度回显。

**浏览器级强缓存**：图片响应带 `Cache-Control: max-age=2592000, immutable`，第二次进入界面连本机代理都不再请求。

**缓存管理面板**：设置 → 系统 → 缓存管理 显示图标缓存、预览图缓存、其他缓存、应用缓存（tpk）的**数量与体积**，支持**导出 tpk 缓存**与分类**清空**。

### 图标多线路回退（v2.11.1 新增）

第三方源常把加速前缀写死在 `icon` 字段里，一旦那条线路对当前网络不通，整片图标就会空白（应用本身仍可安装）。v2.11.1 不再"一条道走到黑"：

- 先剥掉 `gh-proxy` / `ghfast` / `ghproxy.*` 等加速前缀，拿到真实地址（支持多层嵌套与残缺写法）；
- 按 **直连 → 自有加速池前 4 条（服务端下发的测速顺序）→ jsDelivr 镜像 → 源里原始地址** 依次尝试，谁先成功用谁；
- 单线路 4 秒、整图 12 秒预算；加速器把上游 404 包成 200 HTML 错误页的情况会被识别丢弃；
- 全部失败时返回内置灰色占位图（不再出现破图），失败图 5 分钟内不重复回源，同站连续失败 15 次熔断 5 分钟；
- Gitee 的 `blob` 链接自动转 `raw`；GitCode 等站点的 `/blob/` 链接自动兜底 `/raw/`。

### 源站稳定性（v2.11.1 修复）

**空结果不再覆盖缓存**：上游风控或瞬时故障返回空列表时，保留本地已有数据并以"离线"状态提示，不再出现"刷新一下整个界面变白板"。

**列表缓存延长**：应用列表本地缓存 TTL 10 分钟 → **24 小时**，弱网下打开即见。

**刷新不再先清缓存**：刷新改为"成功且非空才写入"，失败保留旧数据，避免断网时双清。

**源测试区分故障类型**：明确区分"源站返回 403（被风控）"与"网络不可达"，排查时不再一概而论"源不可用"。

### 源地址脱敏（v2.11.1 新增）

`sources.json` 中的官方源地址改为编码存储（`url_enc`），明文 `url` 字段留空，避免随手打开配置文件就看到自建服务端地址；源管理页与测速仍按明文正常显示。

### 加速线路面板（v2.11.1 新增）

设置 → 系统 → 加速线路，显示当前线路数量、来源（服务端下发 / 内置兜底）、更新时间、下次检查时间与完整顺序，并提供「重新拉取」按钮。拉取失败时不再只写日志，用户可直接看到是否已退化为内置列表。

### 下载引擎 2.0：服务端实时选线（继承 2.11.0）

**服务端实时选线**：安装时第 1 条候选即服务端 `/apps/` 本地代理入口，服务端在收到请求的**那一瞬间**按健康探测结果现场选线并 302 重定向，天然是最新最优地址。

**候选顺序完全由服务端决定**：客户端按服务端排好序的候选列表从头到尾依次尝试，本地不做跳过、不做否决。

**无本地失败黑名单**：一次网络抖动不会让线路被打入冷宫，连续安装始终顺畅。

### 精准下载统计（继承 2.11.0）

下载校验（文件完整性）**通过之后**才向服务端上报计数，杜绝虚高下载量。

### 卸载数据真正可清除（继承 2.11.0）

卸载向导勾选"清除数据"后，卸载脚本会停进程 → 清空 `@appdata` 数据目录 → 清理 data-share 共享目录与残留 socket。内置三重路径校验，杜绝误删；未勾选则完整保留用户数据。

### 应用管理（继承 2.10.0）

**多源聚合**：从所有启用的软件源并发拉取应用列表，按 `id@platform` 自动去重。

**树状聚合**：官方源可聚合多个三方源应用，无需手动添加即可发现更多应用。

**分类筛选**：15 个固定分类 + Docker/原生类型筛选 + 按源筛选。

**排序与搜索**：按名称、开发者、下载量、更新时间排序；侧边栏全局搜索。

**架构自动适配**：启动时检测本机架构（`runtime.GOARCH`），不兼容的应用自动过滤。

### 双模式引导与安全加固（继承 2.10.0）

**双模式初始化**：首次启动弹窗引导——**用户模式**（开箱即用，默认启用官方源）与**极客模式**（彻底禁用内置官方源，手动添加自建服务端），任何人拿到服务端即可另起炉灶。

**源管理越权拦截**：应用未完成初始化前，后端直接拦截修改/添加源的请求。

**独立自更新隔离**：即使极客模式禁用了官方源，自更新检测（`/api/check-update`）依然可达官方源，客户端永不"断联"。

### 首页数据看板与动态交互（继承 2.10.0）

磨砂玻璃数据看板（总应用/已安装/可更新）；轮播图 5 秒自动切换、悬停暂停；支持 `app:` / `tag:` / `url:` / `tab:` 定向跳转；本地缓存 TTL + 弱网防丢容错，断网不清空本地数据。

### 系统级定向消息推送（继承 2.10.0）

WebSocket 实时推送 + `/api/push/pending` 离线补拉；轻提示 / 强弹窗 / 强制更新三种形态；本地去重防骚扰。

### 官方安装链路与底层管理（继承 2.10.0）

**双段式安装**：下载段完成后走飞牛官方 `app-center/v1`（`download/task` → `install/info` → `install/task` → `install/status`），真实进度回显。

**安装前依赖预检**：解包 FPK 读取 `install_dep_apps`，缺失依赖提前弹窗引导。

**强力修复幽灵应用**：一键物理清理底层目录与进程并重新注册。

**配置备份与恢复**：`@appdata` 一键打包 `.zip` 下载 / 上传恢复。

**一键诊断日志**：自动收集底层安装状态、运行状态与最近 500 行日志。

## 🖥️ 服务端信息

客户端需要配合 **FN软仓服务端** 使用，**兼容 v2.10.4 及以上服务端，服务端无需随本版本升级**。

**服务端镜像**：`docker pull ccr.ccs.tencentyun.com/hhxs2025/fn-appstores-server:2.10.4`

**服务端仓库**：[https://gitee.com/hhxs2025/fn-appstores](https://gitee.com/hhxs2025/fn-appstores)

服务端核心能力：

**动态候选下发**：返回经健康检查与实测测速排序后的 `download_urls` 数组，按健康度排序、坏的靠后。

`/apps/`** 实时选线代理**：本地文件直接 200 返回；GitHub 直链应用现场挑选最优加速规则 302 重定向，命中本地缓存的更快。

**加速器健康检查**：智能探测速度与状态，自动升降级排序；客户端通过 `/api/accelerator/presets` 按序消费，不参与测速与排序。

**轮播图协议 / 定向推送 / 设备统计**：与客户端完整配合。

> 提示：v2.11.1 的缓存与图标回退全部在客户端本地完成，不改变服务端任何下发逻辑；加速线路顺序仍以服务端测速结果为准。
