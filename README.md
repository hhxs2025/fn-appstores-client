## 📖 应用简介

FN软仓是飞牛 OS 上的第三方应用商店客户端，支持**多软件源聚合**。用户可以自由添加自托管服务端地址，浏览、安装、更新飞牛官方应用中心没有的三方应用。

- **项目地址**：[https://gitee.com/hhxs2025/fn-appstores](https://gitee.com/hhxs2025/fn-appstores)
- **服务端镜像**：`docker pull ccr.ccs.tencentyun.com/hhxs2025/fn-appstores-server:2.10.0`
- **平台**：飞牛 OS
- **架构**：x86 / ARM 双架构兼容
- **开源协议**：MIT

> **架构与机器码识别说明**：v2.9.4 起，客户端会优先读取飞牛底层系统注入的机器码（`TRIM_SYS_MACHINE_ID`）作为设备唯一标识，确保**重装系统后不产生虚假新设备**。同时，系统架构（如 `fnos-amd64`）通过请求头精准上报，解决 WebView 读取 `UA` 显示 Win32 的历史遗留问题。

> **✅ v2.9.5 核心变化：安装 / 更新 / 卸载切换到飞牛官方 `app-center/v1` API**。
> 下载段仍由 FN软仓服务端多线路下载 FPK 到本地，安装段全部交给飞牛官方 API 处理。带来三个实际改善：**真实安装进度**、**安装前依赖预检查**、**向导参数支持**。

## ✨ 核心功能

### 应用管理

- **多源聚合**：从所有启用的软件源并发拉取应用列表，按 `id@platform` 自动去重
- **树状聚合**：官方源可聚合多个三方源应用，无需手动添加即可发现更多应用
- **分类筛选**：15 个固定分类 + Docker/原生类型筛选 + 按源筛选
- **排序**：支持按名称、**开发者**、下载量、更新时间排序
- **全局搜索**：侧边栏顶部搜索框，任意页面可直接搜索
- **架构自动适配**：启动时检测本机架构（`runtime.GOARCH`），不兼容的应用自动过滤

### 应用安装与更新

- **双段式安装链路**（v2.9.5 重构）：
  - **下载段**：客户端调 `/api/download`，后端从多条候选线路依次尝试下载 FPK，30 秒 stall 检测 + 首块 5 秒速度检测，低于 100KB/s 自动切线路
  - **安装段**：FPK 下载到本地后，前端调飞牛官方 `app-center/v1` 完成安装——`download/task` 登记本地文件 → `install/info` 预检依赖与读取向导 → `install/task` 提交安装 → `install/status` 轮询获取真实进度
- **安装前依赖预检**（v2.9.5 改善）：v2.9.4 是等 `install-fpk` 报错后才识别依赖缺失，v2.9.5 改为安装前调 `/api/read-manifest` 解压 FPK 读 `install_dep_apps`，主动与飞牛已安装应用对比，缺失依赖直接弹窗引导
- **真实安装进度**（v2.9.5 改善）：不再等 `install-fpk` 跑完才发一次结果，改为轮询 `install/status` 的 `progress` 字段，进度条与实际安装状态同步
- **平滑更新**（v2.9.5 改善）：走飞牛 `update/task` 更新接口，系统自动保留用户数据并平滑升级，不再"卸载 → 重装"粗暴流程
- **向导安装**：2.9.4 和 2.9.5 都支持，只是数据源不同——v2.9.4 从本地 FPK 包的 `wizard/install` 文件读取，参数写 `wizard.env` 传给 `install-fpk --env`；v2.9.5 从飞牛官方 `install/info` 返回的 `wizardInfo` 读取，参数通过 `install/task` 的 `customParameters` 提交

### 底层管理与强力修复

- **智能状态联动**：应用详情页打开时，自动调用底层接口查询真实运行状态。运行中只显示「停止」，已停止只显示「启动」，不再无脑全显。
- **强力修复（专治幽灵应用）**：针对部分设备因底层数据库卡死导致的"应用中心有，桌面无图标/点不开"现象。一键绕过飞牛 CLI 安全拦截，强制物理清理底层目录与进程，并重新注册安装。
- **配置备份与恢复**：
  - **备份**：将 `/vol/@appdata/{app_id}` 下的所有用户配置打包为 `.zip` 下载至本地。
  - **恢复**：上传 `.zip` 备份文件，自动解压覆盖并重启应用。重装系统后数据一键找回。

### 设备与架构精准识别

- **机器码采集**：读取系统底层 ID，配合服务端 2.10.0 实现 100% 精确的设备活跃统计与去重。
- **全链路 Header 注入**：客户端向服务端发起请求时（拉应用、看公告），自动附带 `X-Client-ID`、`X-Device-Type`（如 `fnos-amd64`）和 `X-App-Version`。
- **真实架构显示**：调用 `/api/sysinfo` 获取 NAS 真实 CPU 架构，彻底告别浏览器兼容性导致的显示错误。

### 一键诊断日志

- **位置**：应用详情页新增「导出日志」按钮。
- **内容**：自动收集飞牛底层的安装状态、运行状态，以及 `@appdata` 目录下最后 500 行 `.log` 日志。
- **价值**：遇到"启动失败"或"安装报错"时，生成 `.txt` 报告一键发给开发者，告别"黑盒盲猜"排查。

### 应用评分与收藏

- **5 星评分**：详情页内点击星星打分，本地记录"我的评分"
- **用户身份聚合**：通过统一网关注入的 uid 识别用户，回退到本地 client_id
- **应用收藏**：卡片右上角 ☆ 或详情页「收藏」按钮，设置页可集中查看、清空

### 软件源与系统体验

- **源管理**：支持添加、删除、启用、禁用、测试三方源；官方源不可删除。
- **加速池手动刷新**：设置页一键触发，忽略 TTL 限制强制拉取最新加速节点。
- **系统主题跟随**：默认自动跟随飞牛系统，2 秒轮询 `getPlatformConfig()` 兜底，支持手动深色模式。
- **静态资源自动版本号**：每次请求首页自动计算静态文件 Hash 后缀，改 JS/CSS 后 F5 即生效，告别强刷。
- **公告未读红点**：首页公告列表支持已读标记，红点提示，本地持久化。

## 📜 版本记录

### v2.9.5（当前版本）

**安装 / 更新 / 卸载切换到飞牛官方 `app-center/v1` API**

**✨ 核心变化**

- **安装走官方 API**：安装不再依赖 `appcenter-cli install-fpk`，改为飞牛官方的 `app-center/v1` REST 接口：
  - 下载段：`/api/download` 后端多线路下载 FPK 到本地（保留 v2.9.4 的三层加速 + 本地历史学习能力）
  - 安装段：`download/task` 登记本地 FPK → `install/info` 预检依赖与读向导 → `install/task` 提交 → `install/status` 轮询进度
- **更新走官方 API**：从 v2.9.4 的 `stop → uninstall → install-fpk` 粗暴流程，改为 `update/task` 平滑更新，系统自动保留用户数据
- **卸载走官方 API**：改为 `uninstall/task` + `uninstall/status` 轮询，不再依赖 `appcenter-cli uninstall`

**🔧 行为变化**

- **真实安装进度**：从 v2.9.4 的"install-fpk 执行完才发一次结果"改为轮询 `install/status` 的 `progress` 字段，进度条与实际安装状态同步
- **依赖预检提前**：从 v2.9.4 的"安装失败后捕获 `Required application [X] is not installed`"改为安装前调 `/api/read-manifest` 主动预检，缺失依赖直接弹窗，不用等底层报错
- **向导数据源切换**：向导配置从"本地 FPK 包里的 `wizard/install` 文件"改为"飞牛官方 `install/info` 返回的 `wizardInfo`"；参数传递从"写 `wizard.env` + `install-fpk --env`"改为"`install/task` 的 `customParameters` 数组"。能力本身两个版本都支持，只是数据来源和传递方式变了

**🐛 修复**

- 修复依赖缺失时报错 16005 信息模糊、用户不知道缺什么的问题，现在安装前就会弹窗提示具体依赖名

**🔌 兼容性**

- **服务端 v2.10.0 配套最佳**（提供 `/api/download`、`/api/download/status`、`/api/read-manifest` 接口）
- **旧版服务端**：无上述接口时，`/api/download` 404 → 前端捕获错误并提示"服务端版本过低，请升级"
- **飞牛系统**：要求飞牛 OS 提供 `app-center/v1` 接口

### v2.9.4

**全链路身份识别 + 一键诊断 + 底层管理增强**

**✨ 新增**

- **设备身份与架构识别**：新建 `device.go` 及 `APISysInfo` 接口。客户端启动时生成 `ClientID`，每次网络请求注入 `X-Client-ID` 与 `X-Device-Type`。完美对接 2.10.0 服务端的精准统计系统。
- **一键诊断日志导出**：新建 `diagnostics.go` 及 `APIDiagnostics` 接口。一键抓取应用底层 `status` 状态与 `@appdata` 的最后 500 行 `.log`，直接下载 `.txt` 报告。
- **智能状态联动**：`apps.js` 详情页加载时请求 `/api/app/:app_id/status`，根据返回状态动态隐藏/显示「启动」和「停止」按钮。
- **幽灵应用强力修复**：`manage.go` 新增 `APIRepairApp`。针对飞牛底层数据库卡死导致"无图标/点不开"的应用，直接物理清理 `/var/apps` 及残留目录，强杀进程，重新注册安装。
- **配置备份与恢复**：新建 `backup.go`，新增 `/backup` 与 `/restore` 接口。支持打包与解压 `@appdata` 目录，实现 NAS 玩家梦寐以求的配置无损迁移。
- **安装静默轮询**：`websocket.js` 在收到安装成功指令后，不再死等 12 秒，改为每 3 秒轮询一次 `/api/installed`，系统注册完毕后瞬间刷新界面。

**🐛 修复**
- 修复 WebView 环境下读取浏览器 UA 导致"系统架构"显示为 Win32 的问题，改为直接调用 Go 底层的 `/api/sysinfo` 返回真实架构。
- 修复部分网络环境下应用安装后底部状态栏不更新的问题。

**🔌 兼容性**
- **服务端 v2.10.0 配套最佳**（支持设备精准统计与开发者在线托管）。
- **旧版服务端**：若不支持身份头，会自动忽略，不影响核心安装流程。

### v2.9.3

**应用管理与本地回滚 + 全链路前端功能补全 + 缓存自动管理**

**✨ 新增**
- **应用管理**：停止/启动/重启/卸载 4 个按钮。
- **本地回滚**：升级失败自动卸载新版并重装本地缓存备份。
- **加速池手动刷新**：设置页一键强刷。
- **静态资源自动版本号**：`?v={{.StaticVer}}` 彻底解决前端缓存。
- **应用收藏 / 开发者排序 / 公告未读红点 / 指南移动端适配**。

### v2.9.0 及更早

- **v2.9.0**：修复应用更新功能从未生效问题，引入三层加速兜底、系统主题跟随。
- **v2.8.x**：修复 ARM 安装失败，迁移至 Go+Gin 后端，支持断点续传与 WebSocket 统一管理。

## 🖥️ 服务端信息

客户端需要配合 **FN软仓服务端** 使用，服务端负责聚合应用列表、下发候选下载地址、维护加速器规则、公告和轮播图。

- **服务端镜像**：`docker pull ccr.ccs.tencentyun.com/hhxs2025/fn-appstores-server:2.10.0`
- **服务端仓库**：[https://gitee.com/hhxs2025/fn-appstores](https://gitee.com/hhxs2025/fn-appstores)

服务端 v2.10.0（配套客户端 v2.9.5）的核心能力：

- **开发者纯在线托管**：开发者无需维护 Gitee 仓库，数据保存在服务端本地。
- **应用变更审核**：开发者每次保存应用均需源主审核后上线。
- **设备精准统计**：内置 `devices` 数据表，支持在线状态判定与 CSV 导出。
- **候选 URL 列表下放**：`/api/apps` 与 `/api/app/:id` 返回 `download_urls` 数组。
- **加速器健康检查**：5 秒探测窗口 + 100KB/s 阈值，分 online / degraded 两档。
- **加速器池接口**：`/api/accelerator/presets` 供客户端拉取最新加速站列表。
- **FPK 下载任务管理**（v2.9.5 新增依赖）：`/api/download` + `/api/download/status` 提供后端多线路下载能力。
- **FPK 依赖预读**（v2.9.5 新增依赖）：`/api/read-manifest` 解压 FPK 读取 manifest 依赖。
